# 快乐体系审查与后期不满压力方案

> 审查对象：MPDLL 快乐/不满链路 + SP 数据与 TopPanel UI。
> 目标：把「全政策、科技胜利最后一回合」的不满从 393 提到 800 左右（+407），同时不破坏前中期、不搞纯数值惩罚、联机与旧档安全。
> 结论：不靠「把 1 人 1 不满改成 1.4」这种钝刀，而是补 3 条随规模/时代增长的新来源 + 1 条情境来源，合计约 +405。

| 本地快乐 550 能否抵消人口成本 | 能（净 +0.21/人） | 不能（净 −0.29/人） |

新增来源（明细见 §4）：

| 新来源 | 增量 | 一句话 |
|---|---|---|
| 时代期望 | +136 | 启蒙之后每时代，人口不满 +6%（未来 +36%） |

这个方案的关键不是「加了多少」，而是**新来源的计价口径**：都市病/岗位/同情不走「人口类全局减免」（商品 −52%、个人崇拜 −15% 那套），只吃各自的城市类修正和专属对冲；时代期望则以乘数形式叠在**已折后**的人口不满上。否则全政策玩家一个 −52% 就能把新增内容再打对折。

## 1. 现状审查

### 1.1 数据快照

终局（用户提供）：快乐 1220 = 本地 550 + 信仰转化 120 + 政策 200 + 奢侈品 100 + 建筑全局 250。
不满（截图）：393 = 腐败 16.5 + 人口 377（其中 241 来自普通人口、136 来自专业人员，两行是拆分不是叠加）。
净快乐 827。

### 1.2 代码链路

```
CvPlayer::DoUpdateHappiness()                    CvPlayer.cpp:13310
├─ DoUpdateTotalHappiness()                      CvPlayer.cpp:13356
│   = handicap 默认 + 奢侈品 + 本地城市 + 建筑 + 政策 + 每城 + 宗教
│     + 自然奇观 + 城邦 + 世界议会 + 商路 + 信仰转化
└─ DoUpdateTotalUnhappiness()                    CvPlayer.cpp:14446
    = 腐败 + 被占领城数 + 普通人口 + 被占领人口 + 单位   ← 这里全部按 ×100 累加
      ÷100
      + 公共舆论（意识形态）
      ×（非人类）AIUnhappinessPercent
```

要点：

- 不满按「×100 的定点数」累加，最后统一除 100；**新增来源若加在 `/=100` 之前，必须自己 ×100**，否则会被缩小 100 倍。
- 本地快乐 `CvCity::GetLocalHappiness()` 有硬上限：`iLocalHappinessCap = getPopulation()`（CvCity.cpp:13089）。**本地快乐最多只能 1:1 抵消人口**。
- `GetUnhappinessFromCitySpecialists()` 只在 UI 里做拆分显示，`DoUpdateTotalUnhappiness` 并没有加它——专家没有额外不满，还是按普通人口算。
- 超额快乐每回合 1:1 进黄金时代进度（CvPlayer.cpp:16478），另外还能按政策转文化/科研、按公式转旅游。**所以「净快乐」不是装饰，是滚雪球引擎**。

### 1.3 现有不满来源清单

| 来源 | 公式（×100 后） | 终局量级 | 可对冲 |
|---|---|---|---|
| 腐败（城数） | 每城按 CorruptionLevels：0/2/4/6/8/10 | 16.5 | 市政厅、治安建筑、紫禁城、间谍 |
| 普通人口 | `人口 × 1` × 领袖 × 难度 × 商品 × 越权 | 377 | 本地快乐、商品、政策 |
| 被占领人口 | `人口 × 2` × 修正 | 0（无占领） | 法院、驻军 |
| 被占领城数 | 每城 3 | 0 | 同上 |
| 单位 | `m_iUnhappinessFromUnits` | 0 | 免费单位 |
| 公共舆论 | `max(城数×每城, 人口/每X)` | 0（主流意识形态） | 意识形态 |

**没有的东西**：战争疲劳、隔离（未连首都）、宗教摩擦、饥荒、被掠夺地块、失业、时代期望、规模递增。MPDLL 里 `WarWeariness / UnhappyIsolation / ReligiousUnrest / Famine` 全部为 0 命中（grep 已确认）。

### 1.4 不满构成反推（重要）

截图里「商品供应充足，不满度减少了 52%」是 `GetUnhappinessMod()` 里的商品部分。用它可以把人口反推出来：

- 乘数 = (1 − 0.52) × (1 − 0.20 领袖) × (1 + 0.20 难度) = 0.48 × 0.8 × 1.2 = **0.4608**
- 人口行 240.99 = (总人口 − 专家) × 0.4608
- 专家行 136.39 = 专家数 × 0.4608 → **专家 ≈ 296**
- 两式相加：377.38 = 总人口 × 0.4608 → **总人口 ≈ 819**

再用腐败交叉验证：16.5 = 11 城 × 2（LV1）× 0.75（紫禁城 −25%）→ **11 城**，平均 74.5 人口/城（正好落在 CityScale 的 XXL 60–79 段）。
可工作地块 11 × 37 = 407；专家 296；则失业 ≈ 819 − 407 − 296 = **116 人（约 10.5/城）**。

三个独立数字互相吻合，这个重建基本可信。**唯一不确定**：如果玩家还点了「个人崇拜」（Cult of Personality，−15%），总修正会变成 −67%，人口会变成 ≈1191、专家 ≈430。方案按 819 标定，§5.2 给了高人口情景的换算规则。

### 1.5 结构性诊断（为什么后期一定松）

1. **本地快乐 = 人口上限**，所以「本地快乐」最多只能把人口不满抵消到 0，抵消不了全局快乐。
2. **全局快乐没有对应消耗**：建筑 250 + 政策 200 + 信仰 120 + 奢侈 100 = 670，全是净增。
3. **不满全是固定/线性项**：1/人口、每城 2~10；没有任何一项随时代或城市规模加速。
4. **时代在帮玩家**：奢侈品已经做了「过时代 −1」衰减，但那只压 100 点；政策/建筑/信仰的全局快乐反而随时代和城市数增长。
5. **专家是白拿的**：296 个专家按普通人口算，没有任何额外成本；UI 却单列「专业人员」，容易让人误以为已经收过费了。
6. **全局减免过强**：商品 −52% 一个人就能把人口不满砍半，而它不在「人口不满修正」列表里，玩家看不出来为什么 819 人只产生 377 不满。

一句话：**后期不是「快乐给多了」，是「不满的斜率太平」**。全局快乐随城市数和时代线性涨，不满却只有人口 1:1 和每城固定值。

### 1.6 与 Vox Populi 的对照

| VP 机制 | 做法 | 数值手感 | 本方案态度 |
|---|---|---|---|
| 需求（Distress/Poverty/Illiteracy/Boredom） | 每城按「人口 − 产出/全球中位数」算 0~pop 不满 | 后期主力，通常占不满大头 | **借思想，不整套移植**：需要中位数、AI 重写、和本地快乐体系冲突 |
| 战争疲劳 | `最高疲劳% × 人口 × 0.34%` | 战时很痛，和平为 0 | P4 可选，不承担和平期预算 |
| 宗教冲突 | 少数派人口 × 0.5~1.0 | 中后期 20~60 | P3 备选 |
| 隔离 | 未连首都人口 × 0.34 | 前期痛，后期商路铺满后为 0 | 不做（与现有商路玩法冲突） |
| 饥荒 / 被掠夺 | 食物赤字 ×1.0 / 被掠夺地块 ×0.5 | 战时惩罚 | 低优先 |
| 公共舆论 | 已有 | — | 保留 |
| 傀儡/占领 | 已有且更细 | — | 保留 |

VP 最值得抄的不是具体条目，而是**「不满随时代/世界水平上升」**这个骨架：本模组已经有「奢侈品时代衰减」，同一套设计语言正好可以复用到人口上。

## 2. 设计目标与约束

### 2.1 可接受性六原则

1. **可解释**：每条新不满都能在 TopPanel 里看到数字和原因，不能有隐藏乘数。
2. **有对冲**：每条都有建筑/政策/玩法上的解法，不是纯税。
3. **不惩罚已投入的正当玩法**：精铺、专家经济仍然成立，只是要付「城市变大」的账。
4. **前中期几乎无感**：期望从启蒙开始，都市病从 15 人口开始，岗位只在失业出现后生效。
5. **确定性**：只读同步状态，不掷骰、不读 UI 状态，联机安全。
6. **可调**：系数走 `Defines`，策划改 SQL 即可，不用重编译。

## 3. 方案总览

```
不满 = 腐败 16.5
     + 人口 377 × (1 + 时代期望 36%)
     + 都市病 143
     + 岗位不满 116
     + 世界同情 10
     ≈ 798
```

三条新来源的定位：

- **时代期望**（改人口不满的乘数）：解决「全局快乐随时代涨、人口成本不涨」。
- **都市病**（每城固定+递增）：解决「本地快乐 1:1 抵消人口、城市越大越白嫖」。
- **岗位不满**（失业人口）：解决「人口超过地块+专家席位后没有代价」。
- **世界同情**（情境）：满足「对其他文明人民的同情」的设计意图，量小、有叙事。

## 4. 具体机制

### 4.1 机制 A：时代期望（Expectation）

**规则**：世界时代每超过文艺复兴 1 个时代，人口不满 +6%；未来时代 +36%。

```
期望百分比 E = 6 × max(0, 世界时代索引 − 3)
人口不满 = 人口 × 1 × 领袖 × 难度 × 商品 × 越权 × (100 + E) / 100
```

- 世界时代用 `GC.getGame().getCurrentEraCached()`（与奢侈品衰减同一口径，所有文明时代平均），不是玩家时代。
- 只作用于 `GetUnhappinessFromCityPopulation`，不作用于被占领人口（占领已经 2/人，别叠）。
- 终局：377 × 1.36 = 513，**+136**。

**为什么可接受**：工业之后人民期望更高，是文明类游戏的通用直觉；数值上正好抵消「全局快乐随时代增长」的那部分。

**对冲**：政策「启蒙/公共教育」类 −25% 期望；或维持较低时代（不现实）；或靠商品/政策把人口乘数压低（但期望是乘数，压不没）。

**UI**：加到「人口不满修正」列表，显示「时代期望：+36%」。

### 4.2 机制 B：都市病（Urban Strain）

**规则**：每座自治城市，人口超过 15 后，每 4.5 人口 +1 不满，单城封顶 24。

```
都市病/城 = min(24, floor(max(0, 人口 − 15) / 4.5))
```

- 终局：avg 74.5 → floor(59.5/4.5) = 13 → 11 城 × 13 = **143**。
- 傀儡、被占领、抵抗、焚烧中的城市不计（它们已经按 2/人 + 3/城付费）。
- 只吃「城市类修正」（`GetCityCountUnhappinessMod`、城市数难度、地图规模），**不吃商品/领袖那类人口修正**。

**为什么可接受**：15 人口正好是 CityScale 的 MEDIUM 门槛，玩家在 CityBanner 上已经能看到城市规模；「城市越大，市政越吃力」是最容易被接受的解释。它也精准打在「本地快乐按人口 1:1 上限」这个结构漏洞上。

**对冲**：
- 新增 3 座建筑各 −1（卫生系统 / 公共交通 / 城市公园），单城最多 −3；
- 政策「城市规划」−25%；
- 主动把城市控制在 60（XXL）以下，或接受「大城市 = 高产出 + 高不满」的取舍。

**UI**：TopPanel 新行「都市病：143」；城市界面 tooltip 可选显示本城都市病。

### 4.3 机制 C：岗位不满（Labour）

**规则**：失业人口（既没工作地块、也没进专家席位）每人 +1 不满，单城封顶 12。

```
失业 = GetCityCitizens()->GetNumUnassignedCitizens()
岗位不满/城 = min(12, 失业)
```

- 终局：116 失业（10.5/城）→ **+116**。
- 只算自治城市；傀儡不算（傀儡总督不负责就业）。
- 单城封顶 12 是关键：防止「11 城全 100 人口」时失业爆炸到 300+。

**为什么可接受**：它把「专家席位」变成真正的岗位——多建专家建筑 = 把失业者转成专家 = 不满从 1/人降到 0；不建 = 城市里一堆无业游民。这正好奖励本模组已有的「专家建筑」玩法，而不是惩罚它。

**对冲**：专家槽建筑（大学/工厂/实验室等已有）、岗位类新建筑、控制人口、政策「公共工程」把失业按 50% 计。

**UI**：TopPanel 新行「岗位不满：116」；城市界面可用现成的 `GetNumUnassignedCitizens`。

### 4.4 机制 D：世界同情（Sympathy）

**规则**：每个「人民在受苦」的其他主要文明，你 +5 不满；封顶 20。

判定「受苦」：该文明存活、是主要文明、且 `GetExcessHappiness() < 0`（不满 > 快乐）。

- 终局：假设 2 个文明在受苦 → **+10**。
- 不吃任何百分比修正（固定值，封顶 20）。
- 只读对方同步状态，所有客户端结果一致。

**为什么可接受**：这是「对其他文明人民的同情」的最直译实现，且天然是反向激励——你把别人打崩，自己的民众会不安；结束战争、给援助、传教、让对方变好，都能降。量小，不会成为主要来源，但叙事完整。

**风险**：和平且人人快乐的世界里它是 0，所以**不能拿它当预算主力**（本方案只给了 10）。

### 4.5 配套修正（可选，不进 800 预算）

1. **不满修正下限**：`GetUnhappinessMod()` 夹到 `[−60, +100]`。现在商品 −52% + 个人崇拜 −15% = −67%，人口不满只剩三分之一，新增来源也会被一起砍。夹到 −60 后，**1191 人口那档**会先多出 ≈+80 不满（819 档本来就是 −52%，不受影响）——如果启用，请把都市病从 /4.5 调到 /5，把多出来的 80 抵回去。
2. **UI 透明化**：把 `GetUnhappinessMod()` 作为「其他修正：−52%」并入「人口不满修正」列表；现在它只在 tooltip 底部以「商品供应」单独出现，和人口行对不上账。
3. **超额快乐 → 黄金时代**改为递减（前 100 点 100%，超出部分 25%）。800 不满时仍有 420 净快乐，若不改，黄金时代节奏还是偏快。这条是「压力感」的关键，但会动到现有强度，建议单独评估。

## 5. 数值标定

### 5.1 基准情景（人口 819 / 11 城 / 专家 296 / 失业 116 / 未来时代 / 商品 −52%）

| 项 | 计算 | 数值 |
|---|---|---|
| 现有不满 | 16.5 + 377 | 393 |
| 时代期望 | 377 × 36% | +136 |
| 都市病 | 11 × floor((74.5−15)/4.5) | +143 |
| 岗位不满 | Σ_城 min(12, 失业人口) | +116 |
| 世界同情 | 2 × 5 | +10 |
| **合计** | | **798** |

人均视角：

| 指标 | 现状 | 方案后 |
|---|---|---|
| 人均不满 | 0.46 | 0.96 |
| 本地快乐/人 | 0.67 | 0.67 |
| 本地净（本地−人口不满） | +0.21 | −0.29 |
| 全局快乐/人 | 0.82 | 0.82 |
| 净快乐/人 | 1.01 | 0.52 |

### 5.2 敏感性

| 情景 | 人口/城 | 城数 | 期望 | 都市 | 岗位 | 同情 | 总不满 |
|---|---|---|---|---|---|---|---|
| 基准（74.5 人/城） | 819 | 11 | 136 | 11×13=143 | 116 | 10 | **798** |
| 少城大城（102 人/城） | 819 | 8 | 136 | 8×19=152 | 8×12=96 | 10 | **787** |
| 多城小城（58.5 人/城） | 819 | 14 | 136 | 14×9=126 | 5 | 10 | **670** |
| 高人口（−67% 情景，108 人/城） | 1191 | 11 | 136 | 11×20=220 | 11×12=132 | 10 | **891** |

结论：**少城大城**时岗位项被单城封顶压住、都市病变重，总数与基准接近；**多城小城**时失业几乎消失，总数回落到 670——这是「宽 vs 高」的取舍（宽城多付腐败、少付岗位），不是 bug。

宽城的额外压力应该归腐败而不是都市病：把 `CORRUPTION_LV1` 从 2 提到 3，14 城只多 10.5，杯水车薪；真要压宽城，得在腐败分数里加城市数/人口项，那是腐败系统的独立调整，不在本方案范围。**本方案接受「宽城不满略低」这个特征**，先把高城的账算平。

**高人口情景会超到 890**，此时把都市病除数从 4.5 调到 6.5（→154）、岗位封顶从 12 降到 9（→99），总数为 792。

### 5.3 标定流程（P0 必做）

1. 在 `DoUpdateTotalUnhappiness` 里加一段 `CUSTOMLOG`，把「腐败/人口/专家/期望/都市/岗位/同情」逐项打进日志（仅本地玩家、每 10 回合一次，避免刷屏）。
2. 用一个真正的终局存档跑 1 回合，读出：总人口、城数、专家数、失业数、`GetUnhappinessMod()`。
3. 按 §5.2 的表选一行，微调 `UNHAPPINESS_URBAN_STRAIN_POP_PER_UNHAPPY` 和 `UNHAPPINESS_LABOUR_CAP_PER_CITY` 两个 Defines，直到总数落在 800±30。
4. 把这份日志留在仓库里，作为下次改动的基线。

### 6.1 MPDLL（C++，注释一律英文）

**新 Defines（8 个）**——按现有 `GD_INT_*` 宏，每个 define 4 处各一行（以都市病起点为例）：

```cpp
int CvPlayer::GetUnhappinessFromUrbanStrain() const
{
    const int iStart = GC.getUNHAPPINESS_URBAN_STRAIN_START_POP();
    const int iPerPop = std::max(1, GC.getUNHAPPINESS_URBAN_STRAIN_POP_PER_UNHAPPY());
    const int iCap = GC.getUNHAPPINESS_URBAN_STRAIN_CAP();
    int iSum = 0;
    int iLoop = 0;
    for (const CvCity* pCity = firstCity(&iLoop); pCity != NULL; pCity = nextCity(&iLoop))
    {
        if (pCity->IsPuppet() || pCity->IsOccupied() || pCity->IsIgnoreCityForHappiness()
            || pCity->IsResistance() || pCity->IsRazing())
            continue;
        int iOver = pCity->getPopulation() - iStart;
        if (iOver > 0)
            iSum += std::min(iCap, iOver * 10 / iPerPop);
    }
    return iSum * (100 + GetCityCountUnhappinessMod()) / 100;
}
```

```cpp
int CvPlayer::GetUnhappinessFromSympathy() const
{
    int iSuffering = 0;
    for (int i = 0; i < MAX_MAJOR_CIVS; i++)
    {
        const CvPlayer& kOther = GET_PLAYER((PlayerTypes)i);
        if (&kOther == this || !kOther.isAlive() || kOther.isMinorCiv() || kOther.isBarbarian())
            continue;
        if (kOther.GetExcessHappiness() < 0)

    }

                    iSuffering * GC.getUNHAPPINESS_SYMPATHY_PER_CIV());
}
```

## 7. AI 与难度

- 新来源加在 `DoUpdateTotalUnhappiness` 的 `AIUnhappinessPercent` 之前，**AI 自动享受现有难度折扣**（神级 66%）。
- AI 现有逻辑：`IsEmpireUnhappy()` 时不吞并、不烧城、`IsEmpireVeryUnhappy()` 时人口增长归零。新增来源会让 AI 更保守——这是好事（抑制 AI 无脑铺城），但要在 P1 后专门跑一局观察 AI 城数是否明显下降（阈值：平均城数降幅 ≤10%）。
- 如果 AI 明显变弱：把新来源按 `isHuman() ? 100 : 70` 打折，或把 `HANDICAP_AI_DEFAULT` 的 `AIUnhappinessPercent` 从 100 降到 80。
- AI 不会主动建「减都市病」建筑，P2 需要给这类建筑加 AI 权重（`CvCityAI::AI_ChooseProduction` 里按不满程度加权）。

## 9. 风险与被否决方案

### 9.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 玩家把城市压在 15 人口以下规避都市病 | 精铺变弱 | 可接受：小城本来产出低；如需要，给 25 人口以上额外系数 |
| 失业人数远超预期（高人口情景） | 岗位项暴涨 | 单城封顶 12 |
| 商品/政策减免把期望砍半 | 达不到 800 | 期望是乘数，压不没；必要时夹 `GetUnhappinessMod` 到 −60% |
| AI 变弱 | 后期无对手 | 难度折扣、AI 权重、分阶段观察 |
| 世界同情被「故意打崩对手」反向利用 | 不合理 | 封顶 20，且打崩对手本身代价更大 |

### 9.2 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 把 `UNHAPPINESS_PER_POPULATION` 从 1 提到 2 | 前期直接崩；后期本地快乐仍然 1:1 抵消；没有解决结构问题 |
| 直接砍全局快乐（政策/建筑/信仰） | 破坏已有 build 价值，玩家体验是「被没收」而不是「新挑战」 |
| 整套移植 VP 需求系统 | 要全球中位数、AI 重写、和本地快乐体系冲突，工作量和风险都远超收益 |
| 只加「每城固定不满」 | 不随规模增长，30 城时占比反而变小 |
| 按「超额快乐」收不满（嫉妒/期望落差） | 玩家会觉得「我快乐反而被罚」，不直观；可作 P4 软上限备选 |
| 降低本地快乐上限（按规模 0.9/0.75/0.6） | 单行改动、等效 +150~220，但玩家看到的是「本地快乐被暗改」，可接受性差；留作备用杠杆 |
