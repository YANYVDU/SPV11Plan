### [1] 【严重】卫星发射路径引用「后声明的 local 函数」→ 运行时 nil，全球效果全失效 + 发射单位不被消耗

- **文件**：`Super Power - Remaking of World Order (v 7)/Gameplay/Lua/Utility/UtilityFunctions.lua:165`、`:212`（定义见 `:226`、`:330`）
- **维度**：B（Lua 运行时错误，中断事件处理器）
- **证据**：本次重构把原来的**全局**函数调用改为**局部**函数调用，但被调者定义在调用点**之后**：

```lua
124: local function SatelliteLaunchEffects_Base(unit, city, player)
165:     SatelliteEffectsGlobal_Base(unit);      -- 该 local 在 226 行才声明
226: local function SatelliteEffectsGlobal_Base(unit)
```

  `local function` 不向前可见（词法作用域），165 行的引用在编译期被解析为**全局访问**，而局部定义从不写全局 → `_G.SatelliteEffectsGlobal_Base` 恒为 `nil`。基线 `a7c2416` 此处用的是全局函数 `SatelliteEffectsGlobal(unit)`，前向引用安全，属重构引入的回归。程序化扫描本域 7 个 Lua 文件的 `local function` 前向引用，**仅此两处**命中。
- **失效场景**：任何卫星单位发射时（单机走 `_Base`、联机走 `_MP`）→ `attempt to call a nil value`。紧随其后的 `unit:Kill()` / `SendAndExecuteLuaFunction(unit.Kill)` **不再执行**：

  - 发射单位**不被消耗**，可重复发射并重复叠加建筑。
  单机与联机均稳定复现。
- **建议修复**：在 `:124` 之前补前向声明（注意：SP 仓库注释用英文）

```lua
local SatelliteEffectsGlobal_Base
local SatelliteEffectsGlobal_MP
```

### 2.3 健壮性/一致性（供顺手修，非缺陷）

- **`HasCSUAEffect` 对 `pMinorAI` 未判空**（`CvPlayer.cpp:33195-33196`），同文件同类函数 `HasCSUABeliefPurchaseUA` 有判空；因 `m_pMinorCivAI` 对每个玩家无条件 `FNEW`，实际不可触发。
- **`ApplyEffect` 两个向量分支未乘 `iChange`**（`CvCityStateUAClasses.cpp:2064-2071`、`:2164-2170`）：当前仅以 `iChange=1` 调用，无实际影响；若将来支持 `-1` 增量移除会残留条目。
- **`GetHolyCityYieldModifierPerFollowingCity` 缺 Release 守卫**（`CvCityStateUAClasses.cpp:1335`、`:2635`），只有 `CvAssertMsg`，与同类 getter 的 `i<0 || i>=count` 兜底不一致。
- **内联 SQL 的 `PrepareResults` 返回值未判 NULL 即 `Bind`**（`CvCityStateUAClasses.cpp:958-961` 等），与该文件既有写法一致。
- **`ChooseCSUAPantheonBelief` / `ChooseCSUABelief` 空表返回未初始化值**（`CvReligionClasses.cpp:6473-6476`、`:6522-6525`），可达性低，既有 `ChoosePantheonBelief` 写法相同。
- **`m_iSpyPoints` 插在序列化流中段**（`CvTraitClasses.cpp:5069/5607`），破坏"旧 DLL 读新存档"；本周期其他新成员均已在流尾。
- **`DoCityStateFaith*PurchaseFromMajor` 只对 `eMajor` 做运行期校验**（`CvGame.cpp:210-211`、`2192-2197`），Release 下断言被编译掉。
- **`AnyPlayerHasZOCRangeBonus` 的函数级静态缓存**（`CvUnitMovement.cpp:325-357`）仅按 `getGameTurn()` 失效，同进程载入另一存档且回合号相同时会沿用旧缓存；确定性重算，不构成不同步。
- **队伍级 OB → 玩家级 OB 的语义变化**（`CvDealClasses.cpp:2625/2987`）：成交时只对单个玩家写入，队伍局中队友不再自动获得 OB，需确认是否有意。
- **`DLL_Options.xml:422` 的 `SP_RELIGION_PRESSURE_SELF_FOUNDER_MOD` 在 MPDLL 无对应 CustomModOptions 声明** → 该 `<Update>` 静默匹配 0 行；因代码默认值与 SP 设定值恰均为 33，当前无功能差异，但日后调值会误以为已生效。

### 2.4 行为变更待确认（1 项）

- **`UnitSpecialButtons.lua:1435`**：TokyoRaid 新增了一条原被注释的 `PROMOTION_CARRIER_UNIT` 移除，由注释行变为激活的广播调用。不确定是"单机联机统一"时的有意修正还是误删注释，需对照设计稿确认"东京急袭"是否应保留载体属性。

### 2.5 跨域复核结论（2 项，方向性提示）

- **`Building_DomainEnemyCombatModifierPerGold` 的 -10 在 C++ 侧无下界**（`BuildingEffect.sql:66-69` → `CvUnit.cpp:19786`）：城邦国库 ≥900 金时战斗力修正饱和至 -90%，敌方战斗力被压到基准的 10%。**经复核不会归零、不会转负、不会崩溃**——`CvUnit.cpp:16148-16149`/`16446-16447` 有 `if(iModifier < -90) iModifier = -90;`，`:16154`/`:16462` 有 `return std::max(1, iCombat);` 保底。属平衡问题而非缺陷。
- **维护成本提示**：`CSUA.xml` 中多处同一效果在盟友/朋友档重复定义同一组元素，是 §1[4] 重复累加的直接诱因；后续新增效果建议先确认是否会与既有 class 重叠。
